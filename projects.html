代表專案

這些專案的共同主軸：把 Enterprise IT 中原本依賴人工、經驗與被動處理的問題，轉化成可持續運作的平台。 每個專案都以「營運問題 → 架構決策 → 建立能力 → 量化成果」的方式呈現。

01 · Enterprise Operations Platform

自助部署平台｜Flask + Jenkins + AWX + Ansible

Business Problem

API 主機約 12 台、共 108 支 Java API，RD 幾乎每天更新（最多單日 5 次）， 原本完全依賴二線工程師人工部署，形成營運瓶頸且容易出錯。

Architecture Decisions

OP 不應該輸入指令 ── 隱藏 Linux CLI，改用 Web 操作 保留 Jenkins ── 大量併發動作與 Bash 整合，降低重構成本 採用 AWX ── 權限與稽核管控，圖形化操作 支援 Rollback ── 保留更版紀錄，OP 可自行調用上一版本
Platform BuiltWeb-based 自助部署平台（Flask 前端 → Jenkins/AWX 執行）
Capability標準化部署、自助維運、版本回滾、治理與稽核
Operational Outcome每支 API 部署從 10–15 分鐘縮短至約 3 分鐘
Business Impact每月節省 60+ 部署工時；穩定後約 95% 日常部署不再需要二線工程師介入

02 · Database Resilience & Performance Architecture

MySQL 混合雲災難復原｜Percona XtraBackup + AWS

Business Problem

地端 VMware 的 Backup I/O 會吃光主機資源、拖慢其他 VM；且原本使用會鎖表的 mysqldump 備份， 最近一版備份往往已是數月前，還原後的資料同步耗時最長。

Architecture Decisions

Backup 不應碰 Production ── 由 Slave 執行 Hot Backup 將 replication / backup workload 延伸至 AWS ── 與地端 VMware 生產負載隔離 選擇 Percona XtraBackup ── 第一優先 Hot Backup、第二開源，後續發現可從 Slave 備份 Read / Write Separation ── 讀取流量由雲端 Slave 分攤
Platform Built混合雲 MySQL 主從架構：地端 Master → VPN → AWS Slave → XtraBackup → AWS NFS
Capability不停機熱備份、每日差異備份、異地備援、讀寫分離
Operational OutcomeMySQL Slave RTO 由約 8 小時縮短至 60 分鐘
Business Impact備份不再影響服務、大幅減輕地端 VMware 負載、提升資料庫可復原性

03 · Enterprise Cloud Security Operations Platform

雲端安全監控平台｜WAF + OpenSearch + VirusTotal + Wazuh

Business Problem

導入 AWS WAF 後只有防禦、沒有後續監控與告警；在多人共用的雲端環境中， 資源異動與可疑連線無法被主動發現。公司未購買 SIEM 軟體，需要符合 ISO 27001 合規。

Architecture Decisions

將既有防禦控制延伸為 Visibility → Detection → Investigation → Response 以 Threat Intelligence 驗證 WAF 活動 ── 每小時 Top-10 IP 送 VirusTotal（受免費額度約束，設計 240 queries/day） 疑慮 IP 自動反查 7 天歷史 ── 對應短時間密集攻擊模式 不同 Confidence 對應不同自主度 ── 情資判斷採人工黑名單；Wazuh 行為偵測（Level>7 且 40x>50）自動封鎖
Platform Built開源安全監控平台（OpenSearch/ELK + Graylog + Wazuh + Teams 告警）
Capability威脅可見性、偵測、調查輔助、自動回應、帳號治理、組態監控
Operational Outcome持續偵測未告知變更與可疑 IP，並於 Teams 主動推播；Wazuh 自動封鎖列舉行為
Business Impact通過 ISO 27001；每年節省約 NT$200K 授權費；取代 SOC L1 人力每年節省 2000+ 工時
